# راهنمای مهاجرت به v1.3.0

این راهنما برای اپراتورهایی است که نسخه 1.2.2 را در حال اجرا دارند. **خبر خوب: اگر کاری نکنید، همه چیز مثل قبل کار می‌کند.** لینک‌های ارسال‌شده، سکرت‌ها و اتصال‌های فعلی همگی باقی می‌مانند (سازگاری بایتی، با تست golden تضمین شده).

## ۱. به‌روزرسانی worker.js

- محتوای `worker.js` جدید را در داشبورد کلودفلر (Edit code) جایگزین کنید و Deploy بزنید. همین.
- متغیرهای قبلی همه پذیرفته می‌شوند. چهار متغیر قدیمی دیگر خوانده نمی‌شوند و اگر تنظیم باشند در صفحه وضعیت «ناشناخته» گزارش می‌شوند: `AD_TAG`، `GENERATOR_ENABLED`، `GENERATOR_KEY`، `ACCEPT_GENERATED`. می‌توانید حذفشان کنید.

## ۲. اگر فقط ADMIN_KEY داشتید (حالت legacy) — توصیه: فریز کنید

در این حالت سکرت‌های پروکسی از ADMIN_KEY مشتق شده‌اند. این یعنی:

- هر کس ADMIN_KEY را داشته باشد، می‌تواند سکرت پروکسی را آفلاین محاسبه کند (اگر ADMIN_KEY ضعیف باشد، قابل حدس است).
- با عوض‌کردن ADMIN_KEY همه لینک‌ها می‌شکنند.

**اقدام توصیه‌شده (بدون از کار افتادن هیچ لینکی):**

1. پنل را باز کنید؛ در هشدار «حالت قدیمی سکرت» یک مقدار ۳۲حرفی می‌بینید.
2. همان مقدار را عیناً در متغیر جدید `SECRET` در کلودفلر ذخیره کنید و Deploy بزنید. لینک‌ها عوض نمی‌شوند — همین مقدار همان سکرت فعلی است.
3. حالا می‌توانید ADMIN_KEY را هر وقت خواستید عوض کنید.

## ۳. تغییرات رفتاری که باید بدانید

| تغییر | قبلاً | حالا | چه کنید |
|---|---|---|---|
| ورود به پنل | کلید در URL | صفحه `/login` + کوکی امن | از `/login` استفاده کنید؛ مسیر کلید در URL هنوز کار می‌کند ولی منسوخ است |
| سکرت‌ها بین پورت‌ها | سکرت ۴۴۳ روی همه پورت‌ها کار می‌کرد | هر سکرت فقط روی پورت خودش (سخت‌گیرانه) | لینک/سکرت همان پورت را استفاده کنید؛ برای موقتاً بازگشت به رفتار قدیمی `LEGACY_PORT_SECRETS=1` |
| عمر نشست | ۲۴ ساعت | ۶ ساعت + نوسازی خودکار در پل | هیچ؛ کاربران خودکار ری‌کانکت می‌شوند |
| مسیرهای API | `/api/v1/session` و `/api/v1/ws` ثابت | برای هر دیپلوی از سکرت مشتق می‌شود | هیچ؛ مسیرهای قدیمی تا یک نسخه بعد هم پذیرفته می‌شوند. اگر ابزاری خارجی آدرس API را هاردکد کرده، از `SESSION_PATH`/`WS_PATH` استفاده کنید |
| ظاهر فروشگاه فریب | همه دیپلوی‌ها LUXVEIL یکسان | برند/رنگ/محصولات برای هر دیپلوی متفاوت | هیچ |
| `/status` JSON | متن ثابت | حاوی برند مشتق‌شده | اگر مانیتورینگ روی متن `/status` دارید، به `/health` با بررسی فقط `status` فیلد اکتفا کنید |
| ابطال کاربران | — | `USER_SECRETS` | اختیاری؛ برای دادن لینک اختصاصی به هر نفر و ابطال جداگانه |
| ابطال توکن‌ها | — | `KEY_EPOCH` | اختیاری؛ با تغییر مقدار، همه نشست‌های جاری یک‌باره ری‌کانکت می‌شوند |

## ۴. چک‌لیست بعد از استقرار

1. `https://دامنه شما/panel/status` را باز کنید؛ بخش «Environment» باید متغیرهای شما را «set» نشان دهد و هیچ «unrecognized» نداشته باشد.
2. یک اتصال با یکی از لینک‌های قدیمی تست کنید (باید کار کند).
3. از `/login` وارد شوید و یک لینک جدید از پنل بگیرید و با QR امتحان کنید.
4. اگر `?probe=1` گرفتید، همه DCها OK/FAIL خودشان را می‌بینند — خطاهای DC معمولاً موقتی است.

## ۵. سوالات متداول مهاجرت

- **آیا با آپدیت، کاربران قطع می‌شوند؟** نشست‌های جاری WebSocket هستند و با Deploy قطع می‌شوند (مثل هر آپدیتی)؛ پل خودش در چند صد میلی‌ثانیه ری‌کانکت می‌کند.
- **چرا همه چیز را سخت‌گیرانه کردید؟** سکرت مشترک بین پورت‌ها امضای انگشتی مشترک برای سانسورگر می‌سازد و مسیر URL کلید را در تاریخچه/لاگ‌ها باقی می‌گذارد. این‌ها ارزان‌ترین حفره‌های این پروژه بودند.
- **می‌خواهم دقیقاً مثل قبل باشد.** `LEGACY_PORT_SECRETS=1` و ادامه استفاده از مسیر کلید در URL — ولی هر دو ناامن‌ترند و توصیه نمی‌شوند.
