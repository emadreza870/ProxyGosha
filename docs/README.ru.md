# ProxyGosha — Telegram WEB Proxy on Cloudflare Workers (Русская версия)

> Русский перевод синхронизирован с v1.3.0. Основная и самая полная документация проекта теперь ведётся на персидском языке: [README.md](../README.md). Персидская версия: [docs/README.fa.md](README.fa.md).

## Что нового в v1.3.0

Версия безопасности и производительности. Если у вас был задан только `ADMIN_KEY`, все прежние ссылки продолжают работать побайтово идентично v1.2.2 (покрыто golden-тестами).

- **S1 — независимый SECRET (рекомендуется):** страница настройки генерирует и `ADMIN_KEY`, и 32-символьный hex `SECRET`. В legacy-режиме (только `ADMIN_KEY`) панель показывает предупреждение и точное значение SECRET, чтобы «заморозить» текущие ссылки. Проверка энтропии ADMIN_KEY (рекомендуется 24+ символов).
- **S2 — устойчивость к активному пробированию:** все ошибки на `/api/v1/session`, `/api/v1/ws` и любых неизвестных путях возвращают одинаковый ответ (декой-магазин). Бренд, палитра, товары магазина, favicon и `/health` уникальны для каждого деплоя (производные от секрета). `SESSION_PATH`/`WS_PATH` тоже выводятся из секрета, если не заданы (старые пути принимаются ещё один релиз).
- **S3 — вход в панель по cookie:** POST-форма на `/login`, cookie HttpOnly/Secure/SameSite=Strict, подписанный HMAC, 6 часов. Доступ ключом в URL работает, но объявлен устаревшим. Глобальный троттлинг неудачных попыток в памяти изолята (IP не хранятся).
- **S4 — токены:** HMAC токена привязан к host; TTL сессии по умолчанию 6 часов; мост при переподключении обновляет bootstrap-токен. `KEY_EPOCH` — массовый отзыв всех токенов.
- **S5 — строгая изоляция портов:** каждый порт принимает только свой секрет. Старое поведение (секрет 443 на всех портах) — только с `LEGACY_PORT_SECRETS=1`.
- **S6 — экономия CPU:** ограничение и ранний выход в HMAC-проверках; кэш `caches.default` (60 с) для `DECOY_URL`.
- **S7 — BUILD_SEAL отделён от KDF:** байты seal используются только в legacy-выводе; новые выводы используют фиксированную строку доменного разделения. Авторство — обычная константа.
- **F1 — настоящий upstream-batching:** кадры объединяются до 256 KiB: 2× AES-CTR, 1 запись, 1 WINDOW. Побайтовая эквивалентность покрыта тестами.
- **F2 — подключение к DC:** кэш «последней успешной» пары IP:порт, поэтапный параллельный коннект (2-я попытка через ~400 мс, максимум 2 одновременно, проигравшие закрываются), demote на 60 с. Худший случай < 3.5 с (было ~12 с).
- **F3/F4 — память и копии:** нулевое копирование для одно-кадровых сообщений; глобальный лимит очереди изолята (`MAX_ISOLATE_QUEUED`, по умолчанию 32 МБ) и адаптивное окно под давлением.
- **F5 — переподключение моста:** первая попытка ~200 мс с джиттером, экспонента до 10 с, лимит 12 попыток сохранён.
- **F6 — `CARRIER=auto`:** выбор websocket-lanes/websocket по документированной эвристике.
- **F7 — телеметрия:** индикатор cpuSuspect, EMA задержки по DC, полный отчёт env в `/status`.
- **R1 — пользовательские секреты:** HMAC-секреты из меток, список и отзыв через `USER_SECRETS`. Старые generator-режимы удалены.
- **R2 — панель:** серверные QR-коды, кнопки копирования (с nonce), страница замера задержки портов, понятное предупреждение о workers.dev.
- **R3 — `DC_OVERRIDE`:** переопределение списка DC (JSON с валидацией).
- **R5 — `ALERT_URL`:** опциональный вебхук (по умолчанию выключен, без IP/токенов/секретов).
- **Удалено:** `AD_TAG`, `GENERATOR_ENABLED`, `GENERATOR_KEY`, `ACCEPT_GENERATED` (анализ ME — в `docs/ME-notes.md`).

## Быстрая настройка

1. Создайте Worker, вставьте `worker.js`, Deploy.
2. Откройте адрес Worker — страница настройки предложит `ADMIN_KEY` и `SECRET`. Добавьте оба в Variables and Secrets, Deploy.
3. (Рекомендуется) прикрепите свой домен: `workers.dev` заблокирован в Иране, Китае, России и др.
4. Вход в панель: `https://ваш-домен/login` (или старый `https://ваш-домен/YOUR_ADMIN_KEY` — устарело).
5. Подключение в Telegram: кнопка «Connect in Telegram», QR или вручную сервер/порт/секрет этого порта.

Порты: `443 · 2053 · 2083 · 2087 · 2096 · 8443` — строгая изоляция: секрет работает только на своём порту.

## Переменные окружения (фактически читаемые кодом)

| Переменная | Назначение |
|---|---|
| `ADMIN_KEY` | Обязателен для панели. Ключ администратора (24+ символов рекомендуется). |
| `SECRET` | Рекомендуется. Независимый 32-hex секрет порта 443 и основа остальных. |
| `KEY_EPOCH` | Смена значения отзывает все выданные carrier-токены. |
| `EXTRA_HOSTS` | Дополнительные домены через запятую. |
| `DECOY_URL` | Внешний сайт для декоя (edge-кэш 60 с). |
| `CARRIER` | `websocket-lanes` (по умолчанию) / `websocket` / `auto`. |
| `HOSTNAME` | Белый список доменов (по умолчанию все). |
| `MAX_STREAMS` | Максимум MTProto-стримов на сессию (по умолчанию 6, максимум 32). |
| `SESSION_PATH` / `WS_PATH` | Пути carrier API (по умолчанию выводятся из секрета). |
| `DEBUG` | `true` — диагностические логи. |
| `UP_BATCH_BYTES` | Лимит объединения кадров upstream (262144 = 256 KiB). |
| `DATA_CHUNK` | Размер чанка DC→клиент (64 KiB). |
| `MAX_ISOLATE_QUEUED` | Глобальный лимит очереди изолята (32 МБ). |
| `MAX_QUEUED` | Лимит очереди сессии (16 МБ). |
| `SESSION_TTL` | TTL сессии в секундах (21600 = 6 ч). |
| `BOOTSTRAP_TTL` | TTL bootstrap-токена (3600). |
| `DC_OVERRIDE` | JSON-переопределение DC, например `{"2":["149.154.167.50"]}`. |
| `USER_SECRETS` | Метки пользователей через запятую; индивидуальный отзыв. |
| `LEGACY_PORT_SECRETS` | `1` — вернуть кросс-портовое поведение v1.2.2. |
| `ALERT_URL` | https-вебхук алертов (выключен по умолчанию). |
